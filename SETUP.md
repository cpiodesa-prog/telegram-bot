# Запуск бота-сповіщувача (сесії / виконком / комісії ОМР)

Що це: двічі щодня — о 10:00 та 16:30 за Києвом — GitHub автоматично
запускає `run_daily.py`, який перевіряє три джерела на сайті Одеської
міськради і шле в Telegram усе нове:

- скликання сесій — розпорядження мера з `omr.gov.ua/ua/acts/mayor/`
- засідання виконкому — оголошення з `omr.gov.ua/ua/announce/`
- засідання постійних комісій — графік з `deputat.omr.gov.ua/commissions/schedule/`

Нічого постійно не працює у вас на комп'ютері — все відбувається на
серверах GitHub, безкоштовно.

**Ліміт GitHub Actions:** для приватного репозиторію безкоштовний план дає
2000 хв/міс. Один запуск цього workflow триває приблизно 30-90 секунд
(checkout + встановлення залежностей + сам скрипт, включно з розв'язанням
anti-bot-загадки omr.gov.ua, яка додає ~6-8 сек). Два запуски на день ≈
2-3 хв/день ≈ 60-90 хв/міс. Навіть якщо в тому ж репозиторії вже є інший
щоденний job (типово теж кілька хвилин на день), сумарно це залишається в
межах кількох сотень хвилин на місяць — далеко до ліміту в 2000. Якщо
захочете зовсім без обмежень — досить зробити репозиторій публічним
(Settings → General → Danger Zone → Change visibility): для публічних
репо Actions безлімітні й безкоштовні.

## 1. Створити Telegram-бота

1. У Telegram відкрити **@BotFather** → `/newbot` → дати ім'я й username
   (напр. `omr_events_bot`).
2. BotFather видасть **токен** виду `123456789:AA...` — скопіювати, знадобиться
   на кроці 4.

## 2. Створити канал і додати бота

1. Створити Telegram-канал (публічний або приватний) — куди приходитимуть
   сповіщення.
2. Додати бота в канал як **адміністратора** (Channel → Administrators → Add
   Admin → знайти бота за username).
3. Дізнатись **chat_id** каналу:
   - якщо канал публічний — chat_id це просто `@your_channel_username`;
   - якщо приватний — переслати будь-яке повідомлення з каналу боту
     **@userinfobot** або **@getidsbot**, він покаже id виду `-1001234567890`.

## 3. Залити проєкт на GitHub

Локальний git-репозиторій у цій папці (`telegram-bot/`) вже створений і має
перший commit — можна одразу публікувати. Два варіанти, обрати один:

### Варіант A — GitHub Desktop (без командного рядка)

1. Встановити [GitHub Desktop](https://desktop.github.com/), увійти своїм
   акаунтом GitHub.
2. File → Add local repository → вказати цю папку (`...\oms-website-parser\telegram-bot`).
3. Кнопка **Publish repository** → зняти галочку "Keep this code private"
   якщо хочете публічний репо (unlimited Actions), або лишити приватним
   (теж ок, ліміту вистачить — див. вище) → Publish.

### Варіант B — командний рядок

На github.com створити новий **приватний** репозиторій (без README, без
.gitignore — вони вже є локально), потім у терміналі:

```bash
cd oms-website-parser/telegram-bot
git remote add origin https://github.com/<ваш-акаунт>/<назва-репо>.git
git branch -M main
git push -u origin main
```

При першому push Windows попросить увійти в GitHub — увійти через
браузер, окремо вводити токен вручну не треба.

## 4. Додати секрети в репозиторій

GitHub → ваш репозиторій → **Settings → Secrets and variables → Actions →
New repository secret**:

| Name | Value |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен з кроку 1 |
| `TELEGRAM_CHAT_ID` | chat_id з кроку 2 |

## 5. Перевірити вручну

GitHub → вкладка **Actions** → зліва обрати workflow
"Щоденне сповіщення про сесії/виконком/комісії ОМР" → **Run workflow**
(кнопка справа) → запустити на `main`.

Через ~1 хв перевірити:
- у логах запуску (клік на job "notify") — скільки нових подій знайдено;
- чи прийшло повідомлення в канал (якщо на момент запуску справді є щось
  нове — інакше буде "Нових подій немає", це нормально).

Далі бот працюватиме сам щодня о 10:00 та 16:30 за Києвом. Розклад можна
змінити в `.github/workflows/daily-notify.yml` (рядки `cron`).

## Якщо щось пішло не так

- **Actions run червоний / помилка** — відкрити лог кроку "Run daily check",
  там буде traceback. Найімовірніші причини: сайт omr.gov.ua тимчасово
  недоступний (посилений PoW-захист інколи потребує кількох спроб — код це
  вже враховує, retries=4), або структура сторінки на сайті трохи змінилась
  і регулярку треба підправити — тоді просто скинути мені лог помилки.
- **Немає повідомлень кілька днів поспіль** — це може означати як "справді
  нічого нового", так і "джерело змінило розмітку і скрипт більше не бачить
  рядки". Раз на тиждень варто звіряти вручну з сайтом.
- **Дублікати** — не мають виникати, бо `state/seen.json` комітиться в
  репозиторій після кожного запуску. Якщо він випадково видалений/обнулений —
  наступний запуск надішле всі записи з першої сторінки як "нові".
